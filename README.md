# Nibblearn

![Node.js](https://img.shields.io/badge/Node.js-24%2B-339933?logo=node.js&logoColor=white)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

将视频字幕或采样画面整理为带有来源的学习笔记，支持自定义学习目标和文件保存位置。

当前提供 **pi 扩展**，使用宿主已配置的模型。核心与宿主适配层分离，**DSH 适配尚在规划中**。

[安装](#安装) · [快速开始](#快速开始) · [命令](#命令) · [数据与隐私](#数据与隐私) · [源码结构](#源码结构)

## 功能

- **学习计划**：配置学习目标、已有基础、内容范围、笔记形式和输出语言，支持多个计划。
- **浏览器登录**：使用已安装的 Edge 或 Chrome，在专用窗口登录 Bilibili，无需手动查找或复制 Cookie。
- **字幕获取**：先查询 Bilibili 主字幕接口，无字幕时尝试备用接口；通过 `?p=2` 指定分 P，也可导入 SRT、VTT 或字幕 JSON。
- **课程与合集**：`/learn course` 支持单 BV 全部分 P、明确选择的投稿合集，以及多个链接手动组课。用户确认范围、分别／合并方式与累计用量后顺序处理，保留进度，不自动重试失败任务。
- **画面兜底**：没有可用字幕时，经用户另行确认，可采样画面和底部硬字幕区域。需要已安装的 FFmpeg 与看图模型，不是语音转写或完整观看。
- **学习讲义**：要求模型直接讲解材料中的概念、原理、步骤和例子，并提供自测与检查要点，而非仅列出各时间段的主题；解释深度遵循学习计划，材料缺口明确标注。
- **来源引用**：正文使用简短证据编号，时间戳和字幕原文集中在文末来源索引；画面保留采样时刻，可跳转回看。
- **参考材料**：接受主动添加的 Markdown 或纯文本，将补充说明与视频内容分开标注。
- **草稿审核**：生成后先预览、编辑并确认保存；已有文件内容不同时新增版本，不覆盖原文件。
- **请求保护**：限制请求频率，遇到平台限流暂停访问；失败任务需人工确认重试。

## 安装

需要 **Node.js 24+** 和已配置模型的 **pi 1.4.x**。

```sh
pi install git:github.com/hhhhuichen/nibblearn
```

安装后重新启动 pi，或在当前会话执行 `/reload`。

<details>
<summary>从本地源码运行</summary>

```sh
git clone https://github.com/hhhhuichen/nibblearn.git
cd nibblearn
npm ci --ignore-scripts
npm start
```

也可以在仓库根目录临时加载扩展，不添加安装记录：

```sh
pi -e ./extensions/index.ts
```

</details>

## 快速开始

### 创建学习计划

```text
/learn setup
```

按对话框填写目标和保存目录。整理时，字幕与学习计划会发送到当前模型服务，并消耗对应额度。

### 提供视频或字幕

处理 Bilibili 视频前，先运行 `/learn auth`，选择浏览器并允许打开 Nibblearn 专用登录窗口。首次需在该窗口登录，之后通常可复用登录状态。自行登录、处理验证码后，回到 pi 选择“我已完成登录，检查账号”，确认昵称和 UID 后保存登录态：

```text
/learn auth
/learn video <视频链接或BV号>
```

支持带 `?p=2` 的完整链接和纯 BV 号；b23 短链接需先在浏览器展开。备用字幕无法确认分 P 匹配时，不会误用其他分 P 的字幕。登录凭据的配置方式见[数据与隐私](#数据与隐私)。

没有可用字幕时，插件会在模型与依赖满足条件后询问是否改用采样画面。需要通过 `/model` 选择支持图片输入的模型，并安装 FFmpeg；不会自动下载组件。登录失效、验证码、限流、网络或非 JSON 错误会停止处理，不会被当成“无字幕”自动切换下载方式。备用接口明确返回 404/405 时，会说明其不可用，再让用户决定是否仅做画面概要。

也可以直接导入已有字幕，无需登录 Bilibili：

```text
/learn import <字幕文件路径>
```

支持 SRT、VTT 和字幕 JSON。路径包含空格时加引号。

### 处理整门课程：分 P、投稿合集与多链接

```text
/learn course <视频链接或BV号>
```

单个链接先读取视频目录；若平台提供投稿合集信息，会询问只处理当前 BV，还是处理整个合集。确认合集后，按平台分区和条目顺序枚举各视频的全部分 P，再选择输出方式、确认总数量及模型请求上限。没有合集信息时，仍按单 BV 的全部分 P 处理。

也可显式提供多个视频链接或 BV 号，用空格或换行分隔：

```text
/learn course <BV号1> <BV号2> <视频链接3>
```

手动组课先确认输入列表，再读取这些视频的目录；重复 BV 去重，保留首次出现顺序。无论链接带哪个 `p`，每个选中 BV 都包含全部分 P；不会递归扩展它们各自的合集。

- **合并成文**：一份课程导读、按视频 → 分 P 顺序排列的知识正文，以及统一的补充说明、自测、材料限制和来源索引，一次审核保存为一个 Markdown 文件。没有内容的附录不显示。
- **分别成文**：每个 P 一份讲义，分别审核保存。

选择输出方式或最终确认时取消，都不会启动分 P 内容获取或模型整理。单 BV 模式即使接收带 `?p=2` 的链接，也会明确询问是否处理该 BV 全部分 P。只有用户选择投稿合集，或显式提供多个链接时，才会扩展到其他 BV；不会抓取作者全部投稿、推荐视频或递归关联其他合集。只学习某个 P 时继续使用 `/learn video <链接?p=2>`，不带 p 时该命令仍只处理 P1。

- 投稿合集仅采用视频信息接口内可核对数量的完整列表；缺少条目、数量不符、无有效 BV 标识等情况不进行自动扩展，可改用显式链接列表。暂不支持收藏夹、用户系列、合集页面直链或 b23 短链；请提供其中的视频链接。
- 单次最多 100 个不同 BV、总计 10,000 个分 P，超出会报错，不截取一部分冒充全部。枚举目录也受平台请求频率保护，可能在模型调用前暂停。
- 多视频目录逐项缓存 24 小时，并按登录会话隔离，枚举中断后由用户再次运行可复用已取得的目录，避免从头重复请求。入口视频的合集候选仍重新读取；使用目录缓存时确认框会显示最早缓存时间，近期新增 P 可能尚未体现，范围以本次确认列表为准。
- 每个 P 保留原有材料和最多 **12 次**模型请求限制；N 个 P 理论最多 **12 × N 次**，不是整组只调用 12 次。没有并发轰炸接口，平台请求保护仍然生效，大课程可能因频率预算暂停。
- 两种方式都先逐 P 生成内容。合并时学习计划、目标、作者和页脚只保留一次；各 P 导读集中到课程导读，正文不再重复整套模板。自测、补充说明、参考材料、限制和证据移到统一附录，标明所属 P；完全相同的公共说明合并显示，各章特有的缺口、代码、证据及未知自定义章节保留。
- 合并只做本机结构整理，不额外调用模型对知识内容进行跨 P 语义去重或综合，也不声称完整看过视频。各 P 中间草稿保留，用于恢复和复用；只需保存最终合并稿。编排规则升级后重新运行 `/learn course` 选择合并，可复用匹配的单 P 内容生成新版合并稿，旧合并稿及其人工编辑不被覆盖。
- 中途停止时，合并稿只收录本次已确认完成的章节，并明确列出未收录的 P，标记为部分讲义；一个 P 都未完成则不生成空合并稿。补齐后生成新版本，不覆盖已有部分稿或人工编辑稿。
- 同样的计划、登录会话、分 P 列表和生成规则下，重新运行 `/learn course` 可改选输出方式，已完成内容不重新调用模型。合并稿的用量记录是各章原生成用量的合计，不代表合并新增费用。
- 合并输入的各 P 草稿合计及最终成稿均以现有 `2,000,000` 字符草稿上限控制；超过时明确报错并保留各 P 草稿，不截断内容、不自动改为其他输出方式。章节中存在未闭合代码块时会提示修正，避免后续章节被当成代码。
- 无字幕时仍逐 P 确认画面采样与上传。拒绝、缺少依赖、模型失败、登录失效或限流等都会停止整组，明确指出停止位置，不悄悄跳过。
- `/learn cancel` 可停止任务；已完成草稿及分 P 进度保留在本机。`/learn status` 可查看进度，`running` 也可能是上次异常退出留下的记录。
- 修复问题后，由用户再次运行同一个 `/learn course` 并确认，匹配当前计划版本、登录会话、有序视频／分 P 列表及生成规则的已完成项会复用，不重新调用整理模型。失败的生成任务仍需先 `/learn retry <任务ID>` 人工批准；课程入口不会绕过重试确认。计划、登录会话或分 P 列表变化后，可能需要重新获取材料或生成，不能保证复用。
- 多视频课程为每个视频／P 建立独立引用标识，时间戳回到各自 BV，不把不同视频的时间轴拼接成一条。中断信息明确指出视频和 P；手动组课继续时须使用原链接列表，状态页会保留该列表。
- 完成后用 `/learn review <草稿ID>` 审核保存：合并模式使用合并稿 ID，分别模式使用各 P 草稿 ID；都不自动发布。课程进度记录位于工作目录的 `jobs/course-*.json`，不是源码仓库。

### 可选：无字幕时读取画面

画面模式下载当前账号可访问的 MP4 视频流，在该分 P 全程均匀采样，并把每帧的全景和底部文字区域组合为一张图片。不会依赖评论、弹幕或简介编造课程内容。

FFmpeg 需由用户自行安装。Windows 可在 PowerShell 手动执行：

```powershell
winget install --id Gyan.FFmpeg -e
```

安装后重启终端和 pi，让 PATH 生效；已有其他安装位置可设置 `NIBBLEARN_FFMPEG_PATH` 为程序的绝对路径。平台字幕和字幕导入不需要 FFmpeg。

每个视频流最多下载 **256 MiB**，临时视频处理后删除；最多采样 **24 个时间点**，每张 JPEG 不超过 **3 MiB**，受当前模型图片数量限制时会减少采样数量。图片在本机缓存供复用，每次整理前均需确认图片传输；最多 **12 次**分批模型请求。

**画面草稿明确标注为采样概要**，不包含声音。长视频的采样间隔会变大，可能遗漏口头讲解和一闪而过的文字；主要靠口述的视频仍可能材料不足，不保证还原完整课程。

### 审核并保存

```text
/learn review
```

选择草稿，预览或编辑后确认保存。文件会写入计划指定目录下的 `<计划ID>/` 子目录。

“草稿”指尚待人工审核的学习文档，不是只含标题或时间线的提纲。新生成的文档按学习导读、知识正文、单独标注的补充说明、自测与检查要点、材料缺口及文末来源索引组织。模型只能根据已获得的材料展开讲解；不允许模型补充时，不用外部知识补齐缺失的解释。画面模式仍受稀疏采样限制，不能保证生成完整教程。

讲义生成规则升级后，旧草稿仍保留，不会自动改写或调用模型。重新处理原视频或导入字幕会按新规则生成新草稿并消耗额度；同一规则下成功生成的草稿仍可复用。

## 命令

| 命令 | 用途 |
| :--- | :--- |
| `/learn` | 查看帮助 |
| `/learn setup` | 创建学习计划 |
| `/learn plans` · `/learn use <ID>` | 选择计划 |

## 数据与隐私

- **整理请求的模型输入**：字幕、学习目标和主动提供的参考文本；画面模式另经用户确认后发送采样图片。不包含账号 Cookie、媒体签名地址、成品保存路径或整个 pi 会话历史。
- **账号凭据**：本插件的凭据文件仅在本机保存，不加密。POSIX 使用 `0600` / `0700` 权限，Windows 依赖文件 ACL。
- **浏览器登录**：只使用已安装的 Edge/Chrome，不下载浏览器，不读取日常浏览器配置或其他工具的凭据。用户在 Nibblearn 专用窗口自行登录并处理验证码，程序只读取其中的 Bilibili 会话并通过只读接口验证身份。
- **授权保存**：昵称和 UID 只通过本地对话框确认，Cookie 不显示、不发送给模型或聊天。未确认保存不会替换插件原有凭据。登录和检查由用户操作触发，没有持续后台轮询；登录流程最多等待 10 分钟。
- **专用配置**：Edge 与 Chrome 的配置分别保存，不能混用。专用浏览器会保留已完成的登录状态，包括取消保存时；流程结束仅关闭本次专用窗口，不关闭日常浏览器。请勿分享凭据文件、浏览器配置或含登录信息的截图，仅在可信终端或 RPC 客户端操作。
- **文件保存**：重复保存相同内容会复用已有文件；内容不同时新增 `--v2` 等版本。修改输出目录不会搬迁或删除旧文件。

```text
video-learn/
├── settings.json
├── plans/          学习计划与参考材料

├── edge-bilibili/  Edge 专用登录配置（使用后创建）
├── chrome-bilibili/ Chrome 专用登录配置（使用后创建）
├── materials/      带时间戳的材料与 visual-* 画面缓存
├── drafts/         笔记草稿
├── jobs/           任务状态、缓存索引与用量记录
├── locks/
└── traffic/        请求预算与退避状态
```

可在启动宿主前设置 `NIBBLEARN_HOME`，指定独立工作目录。路径优先级为：

```text
NIBBLEARN_HOME → PI_LEARN_HOME（兼容变量）→ 默认目录
```

登录时选择“自动选择”会遵循 `NIBBLEARN_BROWSER`（`auto`、`edge` 或 `chrome`），未配置时优先 Edge，其次 Chrome。非标准安装位置可通过 `NIBBLEARN_BROWSER_PATH` 指定浏览器程序的绝对路径。

视觉采样通过 `NIBBLEARN_FFMPEG_PATH`、`FFMPEG` 或系统 PATH 查找已有的 FFmpeg。只检测和使用，不安装或下载。

不会自动迁移旧数据或重写已有笔记。工作目录应放在源码仓库之外；凭据、浏览器配置、字幕、草稿和运行记录不应提交到代码仓库。

</details>

Nibblearn **不是安全沙箱**。Pi 与扩展使用当前系统用户的权限，其他已启用工具不受本插件的保存检查约束。需要更强隔离时，应使用独立系统用户、容器或虚拟机。

## 当前限制

- 支持字幕与离散采样画面，不提供音频转写或连续视频理解，也不自动选片、定时学习或跨视频综合。
- 笔记生成不自动浏览网页或独立核查事实。模型补充标注为“未检索核验”，参考文本标注为“用户提供，未独立核验”。
- 时间戳与证据索引经过存在性检查，但引用不代表语义正确、字幕完整、画面覆盖全程或观点已证实。
- 不执行评论、私信、点赞或投稿等平台写操作。遇到验证码、限流、预览或访问限制时停止，不尝试绕过；不支持的分段流或编码会明确报错，不会只处理第一段却声称完整。

<details>
<summary>材料大小、模型用量与重试</summary>

- 单份字幕最多 `120,000` 字符，每个分 P／材料生成任务最多 `12` 次分段模型请求；`course` 将多个单 P 任务顺序执行，累计上限会在确认对话框中列明。
- 单次输出不再固定限制为 `4,500 tokens`，默认采用 pi 当前模型声明的最大输出量（`maxTokens`）。输入占用较大时，按剩余上下文空间降低本次输出上限，不截断输入材料。
- 上下文预算以文本 UTF-8 字节数、每张图片预留 `8,192 tokens` 和 `1,024 tokens` 安全余量估算，不是精确分词或计费结果。模型限制配置无效或没有剩余输出空间时，在请求前报错；实际限制仍以服务端为准。
- 最大输出量是允许的上限，不要求模型写满；部分模型的推理也占用输出预算。放宽上限可能增加耗时与费用，笔记结构与证据校验仍然保留。
- 材料超过限制会明确报错，不静默截断。长材料按段整理，当前没有额外的跨段综合请求。
- 每份参考文本最多 `8,000` 字符；计划最多包含 `10` 份参考材料，合计最多 `16,000` 字符。
- 嵌套模型不提供工具，不执行材料中的命令，不联网查资料。
- 成功调用的嵌套模型用量计入 pi 会话。失败时若服务返回用量，会保存在任务记录；服务没有返回用量时无法确定实际计费。
- 复用草稿不会再次调用整理模型，也不会因输出上限调整而自动重新生成；宿主调度工具的普通对话请求仍可能消耗额度。
- 重试从头整理材料，保留历史用量记录；不会自动发布文件。

</details>

生成笔记需要核对原始材料，不应作为个性化医疗、法律或投资建议。
