# Nibblearn

![Node.js](https://img.shields.io/badge/Node.js-24%2B-339933?logo=node.js&logoColor=white)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

将视频字幕或采样画面整理为带有来源的学习笔记，支持自定义学习目标和文件保存位置。

当前提供 **pi 扩展**，使用宿主已配置的模型。核心与宿主适配层分离；**DSH 完整适配尚未提供**，目前仅进行本地只读状态原型验证，不包含在发布包中。

[安装](#安装) · [快速开始](#快速开始) · [命令](#命令) · [数据与隐私](#数据与隐私) · [源码结构](#源码结构)

## 功能

- **学习计划**：配置学习目标、已有基础、内容范围、笔记形式和输出语言，支持多个计划。
- **浏览器登录**：使用已安装的 Edge 或 Chrome，在专用窗口登录 Bilibili，无需手动查找或复制 Cookie。
- **字幕获取**：先查询 Bilibili 主字幕接口，无字幕时尝试备用接口；通过 `?p=2` 指定分 P，也可导入 SRT、VTT 或字幕 JSON。
- **课程与合集**：`/learn course` 支持单 BV 全部分 P、明确选择的投稿合集，以及多个链接手动组课。用户确认范围、分别成文／资料合并／综合教程方式与累计用量后顺序处理，保留进度，不自动重试失败任务。
- **画面兜底**：没有可用字幕时，经用户另行确认，可采样画面和底部硬字幕区域。需要已安装的 FFmpeg 与看图模型，不是语音转写或完整观看。
- **教程式讲义**：按学习目标筛选核心问题，不求录全字幕；围绕规则、代表性例题、判断方法和适用边界展开。例题保留条件、步骤、结果与解释，区分材料原例与据材料推导；正文阶段不默认生成课后自测或复习清单。
- **可选学习辅助**：正文完成后运行 `/learn practice <正文草稿ID>`，另行选择自测题与答案、复习清单或两者，确认用量后生成独立草稿；失败不影响正文。
- **来源引用**：正文使用简短证据编号，时间戳和字幕原文集中在文末来源索引；画面保留采样时刻，可跳转回看。
- **参考材料**：接受主动添加的 Markdown 或纯文本，将补充说明与视频内容分开标注。
- **草稿审核**：正文默认保留来源索引，也可在审核时选择本机生成独立的无索引阅读版，不增加模型请求。可用系统默认 Markdown 应用打开私有审核副本，也可仅显示路径或使用终端编辑器；外部编辑保存后回到 pi 确认，才写入成品目录。已有文件内容不同时新增版本，不覆盖原文件。
- **请求保护**：限制请求频率，遇到平台限流暂停访问；失败任务需人工确认重试。

## 安装

需要 **Node.js 24+** 和已配置模型的 **pi 1.4.x**。

```sh
pi install git:github.com/hhhhuichen/nibblearn
```

安装后重新启动 pi，或在当前会话执行 `/reload`。

<details>
<summary>从本地源码运行</summary>

```sh
git clone https://github.com/hhhhuichen/nibblearn.git
cd nibblearn
npm ci --ignore-scripts
npm start
```

也可以在仓库根目录临时加载扩展，不添加安装记录：

```sh
pi -e ./extensions/index.ts
```

</details>

## 快速开始

### 创建学习计划

```text
/learn setup
```

按对话框填写目标和保存目录。整理时，字幕与学习计划会发送到当前模型服务，并消耗对应额度。

### 提供视频或字幕

处理 Bilibili 视频前，先运行 `/learn auth`，选择浏览器并允许打开 Nibblearn 专用登录窗口。首次需在该窗口登录，之后通常可复用登录状态。自行登录、处理验证码后，回到 pi 选择“我已完成登录，检查账号”，确认昵称和 UID 后保存登录态：

```text
/learn auth
/learn video <视频链接或BV号>
```

支持带 `?p=2` 的完整链接和纯 BV 号；b23 短链接需先在浏览器展开。备用字幕无法确认分 P 匹配时，不会误用其他分 P 的字幕。登录凭据的配置方式见[数据与隐私](#数据与隐私)。

没有可用字幕时，插件会在模型与依赖满足条件后询问是否改用采样画面。需要通过 `/model` 选择支持图片输入的模型，并安装 FFmpeg；不会自动下载组件。登录失效、验证码、限流、网络或非 JSON 错误会停止处理，不会被当成“无字幕”自动切换下载方式。备用接口明确返回 404/405 时，会说明其不可用，再让用户决定是否仅做画面概要。

也可以直接导入已有字幕，无需登录 Bilibili：

```text
/learn import <字幕文件路径>
```

支持 SRT、VTT 和字幕 JSON。路径包含空格时加引号。

### 处理整门课程：分 P、投稿合集与多链接

```text
/learn course <视频链接或BV号>
```

单个链接先读取视频目录；若平台提供投稿合集信息，会询问只处理当前 BV，还是处理整个合集。确认合集后，按平台分区和条目顺序枚举各视频的全部分 P，再选择输出方式、确认总数量及模型请求上限。没有合集信息时，仍按单 BV 的全部分 P 处理。

也可显式提供多个视频链接或 BV 号，用空格或换行分隔：

```text
/learn course <BV号1> <BV号2> <视频链接3>
```

手动组课先确认输入列表，再读取这些视频的目录；重复 BV 去重，保留首次出现顺序。无论链接带哪个 `p`，每个选中 BV 都包含全部分 P；不会递归扩展它们各自的合集。

- **资料合并**：按视频 → 分 P 编排，合并公共栏目，不进行语义综合，不增加综合请求。保留详细来源，适合资料归档。
- **分别成文**：每个 P 一份讲义，分别审核保存。
- **综合教程**：先取得各 P 草稿，再单独确认额外预算与主题规划，跨视频选材、去重和重编正文，使用简短来源定位。不是零费用的拼接；见[将已有讲义重编为个人教程](#将已有讲义重编为个人教程)。

选择输出方式或最终确认时取消，都不会启动分 P 内容获取或模型整理。单 BV 模式即使接收带 `?p=2` 的链接，也会明确询问是否处理该 BV 全部分 P。只有用户选择投稿合集，或显式提供多个链接时，才会扩展到其他 BV；不会抓取作者全部投稿、推荐视频或递归关联其他合集。只学习某个 P 时继续使用 `/learn video <链接?p=2>`，不带 p 时该命令仍只处理 P1。

- 投稿合集仅采用视频信息接口内可核对数量的完整列表；缺少条目、数量不符、无有效 BV 标识等情况不进行自动扩展，可改用显式链接列表。暂不支持收藏夹、用户系列、合集页面直链或 b23 短链；请提供其中的视频链接。
- 单次最多 100 个不同 BV、总计 10,000 个分 P，超出会报错，不截取一部分冒充全部。枚举目录也受平台请求频率保护，可能在模型调用前暂停。
- 多视频目录逐项缓存 24 小时，并按登录会话隔离，枚举中断后由用户再次运行可复用已取得的目录，避免从头重复请求。入口视频的合集候选仍重新读取；使用目录缓存时确认框会显示最早缓存时间，近期新增 P 可能尚未体现，范围以本次确认列表为准。
- 每个 P 保留原有材料和最多 **12 次**模型请求限制；N 个 P 理论最多 **12 × N 次**，不是整组只调用 12 次。没有并发轰炸接口，平台请求保护仍然生效，大课程可能因频率预算暂停。
- 三种方式都先取得逐 P 内容。资料合并时学习计划、目标、作者和页脚只保留一次；各 P 导读集中到课程导读，正文不再重复整套模板。旧稿已有的自测、补充说明、参考材料、限制和证据移到统一附录，标明所属 P；完全相同的公共说明合并显示，各章特有的缺口、代码、证据及未知自定义章节保留。
- 合并只做本机结构整理，不额外调用模型对知识内容进行跨 P 语义去重或综合，也不声称完整看过视频。各 P 中间草稿保留，用于恢复和复用；只需保存最终合并稿。编排规则升级后重新运行 `/learn course` 选择合并，可复用匹配的单 P 内容生成新版合并稿，旧合并稿及其人工编辑不被覆盖。
- 中途停止时，合并稿只收录本次已确认完成的章节，并明确列出未收录的 P，标记为部分讲义；一个 P 都未完成则不生成空合并稿。补齐后生成新版本，不覆盖已有部分稿或人工编辑稿。
- 同样的计划、登录会话、分 P 列表和生成规则下，重新运行 `/learn course` 可改选输出方式，匹配的已完成单 P 内容不重新调用整理模型；综合教程仍需单独确认综合用量。合并稿的用量记录是各章原生成用量的合计，不代表合并新增费用。
- 合并输入的各 P 草稿合计及最终成稿均以现有 `2,000,000` 字符草稿上限控制；超过时明确报错并保留各 P 草稿，不截断内容、不自动改为其他输出方式。章节中存在未闭合代码块时会提示修正，避免后续章节被当成代码。
- 无字幕时仍逐 P 确认画面采样与上传。拒绝、缺少依赖、模型失败、登录失效或限流等都会停止整组，明确指出停止位置，不悄悄跳过。
- `/learn cancel` 可停止任务；已完成草稿及分 P 进度保留在本机。`/learn status` 可查看进度，`running` 也可能是上次异常退出留下的记录。
- 修复问题后，由用户再次运行同一个 `/learn course` 并确认，匹配当前计划版本、登录会话、有序视频／分 P 列表及生成规则的已完成项会复用，不重新调用整理模型。失败的生成任务仍需先 `/learn retry <任务ID>` 人工批准；课程入口不会绕过重试确认。计划、登录会话或分 P 列表变化后，可能需要重新获取材料或生成，不能保证复用。
- 多视频课程为每个视频／P 建立独立引用标识，时间戳回到各自 BV，不把不同视频的时间轴拼接成一条。中断信息明确指出视频和 P；手动组课继续时须使用原链接列表，状态页会保留该列表。
- 完成后用 `/learn review <草稿ID>` 审核保存：合并模式使用合并稿 ID，分别模式使用各 P 草稿 ID；都不自动发布。课程进度记录位于工作目录的 `jobs/course-*.json`，不是源码仓库。

### 将已有讲义重编为个人教程

不必重新下载视频，也不必重新生成所有分 P 草稿：

```text
/learn tutorial <课程任务ID或已有合并稿ID>
```

ID 可从 `/learn status`、生成结果或合并稿开头的 `draft_id` 获取。必须保留工作目录中的原始单 P 草稿、材料和课程进度；只剩导出的 Markdown 文件不能恢复综合来源。入口只接受 ID，不直接读取任意文件路径。

1. **本机选取输入**：从既有单 P 草稿提取知识块、已许可的补充及限制，不把整份导读、题库、复习清单或长字幕引文索引再次送给模型。原例、不同数据集、画面证据与未核验补充分开标识。
2. **先确认费用**：首次最多额外 **9 次请求**（1 次规划 + 最多 8 章编写），单次输出仍遵循当前模型上限。它独立于原有单 P 的 12 次请求预算；不是默认增加所有任务的请求数。
3. **确认学习路线**：规划按知识依赖分章，相同概念集中解释或明确省略原因；全部素材 ID 必须归入章节或取舍记录。用户确认章节和取舍后才继续写正文，取消会保留已付规划及用量。
4. **编写正文**：以问题、概念、必要推导和代表性例子组织，不机械沿用“条件/步骤/结果”模板；不生成课后自测或复习清单，附加字段不再是正文通过校验的条件。来源、材料缺口和取舍记录仍保留。正文使用带类型的短来源编号，先跳到文末知识点，再选择视频时间定位。附录显示视频名称、BV／P，每个知识块最多显示按时间排序的前三处可点击回看入口，不代表重要性排序或完整证据。超过三处时，全部离散时间以紧凑时间表保留在同一 Markdown 的折叠项中，其他时刻可在本组原视频中手动定位，不再逐条重复长 URL；完整来源也仍保留在本机任务记录。不合并相邻或跨间隔的定位，采样画面仍只标采样时刻。折叠使用程序生成的 `<details>`，不是模型提供的 HTML；不支持该标签的阅读器可查看 Markdown 源码中的完整时间表。补充、用户参考、材料疑点分别标注，不伪造视频时间。
5. **审核保存**：只生成新的综合教程草稿，用 `/learn review <新草稿ID>` 审核保存；旧单 P 草稿、合并稿、人工修改及已发布文件不覆盖。

综合不调用 Bilibili、浏览器或 FFmpeg，不重新上传图片/音频，仅处理既有文本。采样画面章节仅使用旧稿描述，不代表重新看图或听过讲解。来源定位会与本机材料核对，但这是 ID/时间定位校验，**不是对原稿观点、推导和代码的事实核验**；旧模型笔记中的错误仍可能延续。缺失材料不能靠综合自动补齐。

- **标题与主线**：教程正文小节由程序统一编号为“章号.小节号”；仅识别并去掉与当前位置一致的简单列表前缀，不猜测删除年份、版本号或小数。规划提示要求工程材料形成可导航的集中流程，不强制增加独立章节或扩写无来源的部署方案。
- **章节衔接**：同一次章节输出附带“已讲概念与规则、局部符号及案例约定”的简短教学摘要，保存在检查点供后续章节参考，不增加模型请求。每个前章的传入摘要连同标识最多 2,400 UTF-8 字节，超限只省略完整摘要条目并标记数量，不截断公式或素材正文。旧检查点缺少摘要，或可选摘要格式无效时，退回明确标记的标题提示，不让辅助字段阻断有效正文。摘要是不可信写作上下文，不是新证据，不能据此混用案例或保证完全去重；增加的输入仍可能消耗额度。
- **缺口编排**：规划阶段备注保存在任务中，不直接当成最终材料缺口；章节编写结合完整素材复核。全文共性说明统一展示，具体缺口标明所属章节；完全相同的条目合并并保留适用章节，不模糊删除相近但不同的疑点。生成规则要求按本章教学目标判断缺口，通常优先写 0–3 条核心问题，但这不是新增校验上限；影响结论、复现或用户目标的独立问题仍须保留。定性类比不机械列举缺失的运动参数或训练硬件；已有生成代码时区分“可尝试复算”和“结果一致性未保证”，不因缺少逐点坐标就断言无法复现。此部分依赖模型遵循提示，不保证自动精简到指定数量。
- 综合输入最多 500 个知识／补充／限制块、合计 2 MiB；规划索引控制在 90,000 UTF-8 字节、每章素材 JSON 控制在 60,000 UTF-8 字节以内。索引只含标题、类型、大小与有限预览，不能代替全文，规划仍可能误判取舍。超出会明确停止，不静默截断素材。宿主模型上下文较小时仍可能请求前报错，需要缩小范围或更换模型。
- 当前计划与原课程版本必须一致。未允许模型补充时，不采用旧稿模型补充块；当前计划已提供的参考文本仍以未核验参考身份单独处理。确认框会说明排除数量和画面材料数量。
- `/learn course` 选择综合教程时，仅在各 P 全部成功后进入额外确认；课程中断不会自动继续综合。独立 `/learn tutorial` 可在明确确认后处理已完成部分，并在成稿标明素材未齐。
- 规划、成功章节及累计用量逐步保存在 `jobs/tutorial-*.json`；素材清单在本机 `jobs/manifest-*.json`。这些都是私有工作数据，不属于源码仓库。合成成功稿的用量是综合阶段各次尝试的已知用量合计，不含此前单 P 生成费用。
- 失败或取消不自动重试。由用户再次运行 `/learn tutorial <综合任务ID>`，重新确认后只继续未完成步骤；单次确认最多 9 次新增请求，已消耗费用不退回，服务未返回用量时计费未知。既有单 P 的人工 `/learn retry` 策略不变。
- 综合引用列表中，同一个有效 ID 的重复项仅在本机去重，不增加模型请求；空列表、未知或跨章 ID、跨章重复分配及素材遗漏仍拒绝，并指出具体字段。不会猜测替换 ID、删掉无效引用后冒充有效正文。
- 章节提示新增紧凑写作目标和本章可用 ID 清单；目标不是长度下限或截断规则，不要求模型写满，不以省掉必要条件和例题换取短文。输出超限后经用户确认续写，会向该章提供上次已知输出上限；不自动增大额度、拆分追加请求或重试。
- 综合任务在 `failures` 中最多保留最近20次失败的阶段、章号、尝试次数和已完成进度；模型失败另保留安全的结束类型、实际输出上限及上下文估算，不保存失败响应正文、服务端错误原文、请求头或凭据。续写成功不会抹掉这份诊断历史；这不能追溯恢复升级前未记录的底层原因。
- 规划规则、来源正文或目标改变后可能形成新任务；已成功的相同内容会复用，不再次调用模型。章节级引用必须属于已分配素材，未采用的素材须说明取舍；这些机械检查不能保证实际教学质量或语义去重完全正确。

### 可选：正文完成后生成自测与复习清单

```text
/learn practice <正文草稿ID>
```

支持单视频／导入字幕讲义、资料合并稿和综合教程。只接受本机已有的正文草稿 ID，不读取任意文件路径，也不对学习辅助草稿再次出题。正文可以先单独 `/learn review` 审核保存；不需要等出题成功才能使用。

1. 选择 **自测题与参考答案**、**复习清单**或**两者**。
2. 确认额外用量：按文本段落与完整代码块分批，每批一次请求，整份学习辅助任务最多 **12 次**。对话框显示实际批次数、可复用批次及本次最多新增请求数，不自动开始第二阶段。
3. 生成独立的学习辅助草稿，题目与参考答案分开呈现，保留对应正文快照的文本块编号与行号。不会把题目追加进原稿，不覆盖正文或已发布文件；用 `/learn review <学习辅助草稿ID>` 单独审核保存。

- 输入是所选正文草稿去除开头元数据区后的文本，以及学习目标、已有基础等必要计划字段；正文中的来源索引、旧题目、补充与人工编辑也会发送，请确认不含不愿共享的内容。不发送账号凭据或整个会话，不重新下载视频或上传图片、音频。
- 自测依据的是既有模型草稿或用户编辑，不是重新核验的视频材料；可能延续旧稿错误或画面缺口。引用仅核对正文块是否存在，不证明答案正确，也不承诺覆盖全部知识点。不能依据缺失内容编造题设或答案。
- 通常每批建议 3–6 题、3–8 项复习任务，**不是硬性题量要求**，材料不足可以为空。保留防止失控输出的安全上限（每批 50 题、100 项复习任务），不再受正文原有的 4 题／5 项门槛约束。文本长度、来源有效性、请求预算等校验仍生效；正文的小节和大小限制此次不变。
- 成功批次、失败信息与累计已知用量保存在 `jobs/practice-*.json`，正文文本块快照在 `jobs/practice-source-*.json`。这些是私有工作数据，不是已发布文件。
- 失败或取消时，正文不受影响，不自动重试。再次运行 `/learn practice <同一正文草稿ID>`、选择**相同类别**并重新确认，才继续未完成批次；失败请求可能已收费。`/learn status` 可查看未完成学习辅助任务。
- 相同计划、正文内容与类别的成功草稿可直接复用；修改正文或更换类别会产生新任务，旧草稿保留。生成过程中正文或计划改变时停止，不发布与当前内容不一致的结果。
- 每批正文 JSON 最多 60,000 UTF-8 字节，按段落／代码块分批，不切断代码或静默丢弃长文本。单块太大、总批数超限或模型上下文不足时明确报错，请改用较小的正文草稿。

**升级兼容**：已成功的旧综合教程仍原样复用，不删除其自测。本次章节衔接、来源导航与数学排版优化不主动使已完成缓存失效，也不重排人工编辑；新生成及未完成任务的后续编写使用新规则。未完成的综合任务保留已付规划和成功章节，可继续使用原 `/learn tutorial <综合任务ID>`；后续只写正文。旧检查点里的自测／清单保留在任务记录中，不插入新组装的正文稿。单视频讲义采用新版正文生成规则，旧草稿不会被自动改写。

### 可选：无字幕时读取画面

画面模式下载当前账号可访问的 MP4 视频流，在该分 P 全程均匀采样，并把每帧的全景和底部文字区域组合为一张图片。不会依赖评论、弹幕或简介编造课程内容。

FFmpeg 需由用户自行安装。Windows 可在 PowerShell 手动执行：

```powershell
winget install --id Gyan.FFmpeg -e
```

安装后重启终端和 pi，让 PATH 生效；已有其他安装位置可设置 `NIBBLEARN_FFMPEG_PATH` 为程序的绝对路径。平台字幕和字幕导入不需要 FFmpeg。

每个视频流最多下载 **256 MiB**，临时视频处理后删除；最多采样 **24 个时间点**，每张 JPEG 不超过 **3 MiB**，受当前模型图片数量限制时会减少采样数量。图片在本机缓存供复用，每次整理前均需确认图片传输；最多 **12 次**分批模型请求。

**画面草稿明确标注为采样概要**，不包含声音。长视频的采样间隔会变大，可能遗漏口头讲解和一闪而过的文字；主要靠口述的视频仍可能材料不足，不保证还原完整课程。

### 审核并保存

```text
/learn review
```

选择正文草稿后，先选择文档版本，第一项为默认的**带来源索引**；也可选择**无索引阅读版**。随后再选择审核方式：

- **外部应用打开 Markdown（推荐）**：导出私有审核副本，并请求运行 pi 的电脑使用系统默认 `.md` 应用打开。可将 `.md` 关联到你已安装的 Typora、VS Code 等应用；插件不会安装阅读器，也不保证默认应用有 Markdown 渲染能力。
- **只显示审核文件路径**：不启动应用，按显示的路径自行打开。适合远程／RPC；文件位于运行 pi 的电脑，不是 RPC 客户端的本机。
- **仍使用终端编辑器**：保留原有审核方式，适合短文档。

外部审核时，在应用中查看或编辑并**保存为 UTF-8**，然后回到 pi 选择“已在外部保存，读取审核文件”，再确认成品保存。修改只保存到应用内存、或“另存为”到其他路径，不会被插件读到。正式文件仍写入计划指定目录下的 `<计划ID>/` 子目录。

- 审核副本位于插件工作目录的 `reviews/<草稿ID的哈希>/review-*.md`，不是成品目录，不会自动加入知识库。`review.json` 只记录对应草稿和版本，勿手工修改。
- 相同正文的未完成审核会继续使用现有副本，不覆盖外部编辑。取消“读取审核文件”时不导入修改；读取后取消最终发布，会保留已读入的本地草稿。审核副本也保留，不自动删除，以免丢失未完成的修改。
- 原草稿已被其他操作修改且与副本分叉，或副本已移动／删除时，会询问是否从当前正文创建新副本；旧文件不覆盖。审核期间草稿被其他操作修改，或最终确认期间审核文件又变化，会停止发布，要求重新审核。
- 打开应用失败时会显示提示和文件路径，可手动打开后继续；打开文件本身不等于确认保存。Windows 使用系统关联应用，macOS 使用 `open`，Linux 使用 `xdg-open`；没有图形桌面时请选择路径或终端方式。
- 外部阅读器的渲染、远程图片／链接加载及云同步由其自身设置决定，请使用可信应用。插件不把审核正文发送给模型或联网服务，不自动迁移到 Obsidian 等知识库。
- 审核文件只接受普通 UTF-8 文件，拒绝链接、空内容和超出大小限制的文件。`/learn save` 仍是同一审核流程的别名，不会绕过确认。

#### 可选：无索引阅读版

运行 `/learn review <带索引原稿ID>`，选择“无索引阅读版”，再按原有流程查看、编辑、读取修改并确认保存。

- 支持字幕讲义、合并讲义及综合教程；自测／复习清单保持原有正文依据索引，不参与此转换。
- 只在本机去掉程序生成的正文证据编号及文末来源／时间定位索引；知识正文、公式、代码、目录、材料缺口、取舍及未核验说明保留。采样画面的“无声音、非连续观看”和补充／参考的非原话身份仍标明。基本视频出处与普通链接不等同于索引，不机械删除。
- 生成独立草稿，标题标明“无索引阅读版”，记录原稿 ID 与正文快照哈希；带索引原稿、来源材料和已有成品不修改。转换用量为0，不调用模型，不下载或重新分析视频，也不补全知识和代码缺口。
- 仍须 `/learn review` 人工审核并确认成品保存；仅选择版本或创建审核副本不算发布。选择到已有阅读版时直接审核它；要回到带索引版本，请选择记录中的原稿 ID。
- 相同原稿快照复用已有阅读草稿，不覆盖其中尚未发布的编辑；原稿内容变化后创建新的阅读快照，旧版保留。对无法安全识别的自定义索引、悬空引用或未闭合代码块会拒绝自动转换，不冒险删正文。

“草稿”指尚待人工审核的学习文档，不是只含标题或时间线的提纲。新生成的正文文档按学习导读、知识正文、单独标注的补充说明、材料缺口及文末来源索引组织；自测和复习清单改由可选的 `/learn practice` 单独生成，不再让附加内容格式问题阻断正文。没有内容的可选栏目不显示。模型只能根据已获得的材料展开讲解；不允许模型补充时，不用外部知识补齐缺失的解释。画面模式仍受稀疏采样限制，不能保证生成完整教程。

教程编写遵循以下规则：

- **选材而非抄全**：删除闲聊、宣传、重复演示与无关旁支；同一批材料按知识依赖重组，不能为了压缩而删掉重要前提、反例和例外。
- **用例子教方法**：材料足够时给出代表性例题；计算说明参数、单位、公式、代入和解释，代码说明已知环境与关键步骤。例题必须提供完整字段和有效的本批证据索引，不强制每节都造一个例子。
- **分清事实与推导**：“材料原例”不能擅改原始条件；“据材料条件推导”只对材料已给出的规则和条件作演算，并显式标注，不代表原话或额外核验。新编例子或新增背景仍受模型补充许可约束，不准混作材料证据。
- **比较与纠疑**：用有依据的比较维度讲清相近概念；区分课程约定和通用结论。字幕缺字段、数字、版本或画面不可见时保留疑点，不自动补成确定事实；不能声称代码已执行或官方资料已查证。
- **正文与学习辅助分开**：材料原例及必要推导仍属于正文；新编课后自测、参考答案和复习清单由 `/learn practice` 独立生成、确认预算和审核。既有旧稿不自动删改。
- **数学排版**：新生成的字幕讲义、综合教程及可选学习辅助统一要求短公式用 `$...$`，独立公式用单独成行的 `$$` 包围，并正确转义 JSON 中的 LaTeX 反斜杠。代码仍保留代码格式；不猜测改写数学含义，不自动补缺失的系数或条件。综合教程组装时，仅对独立、闭合且通过保守结构检查的 `$$` 公式块清理末尾中文句号；代码、行内公式、文本分组、逗号、分号、小数点及有歧义的公式保持原样，检查点原文不变。请使用支持 Markdown 数学的阅读器或开启其数学渲染；普通 Markdown 应用可能只显示公式源码，插件不安装渲染组件，也不保证所有阅读器表现一致。
- **同材料分批衔接**：下一批仅附带前几批最近的小节标题（最多 12 个，每个最多 120 字符）作为不可信写作提示，不提供整段历史，不把标题当证据，也不因此省略新条件。本次没有额外规划或综合请求，请求次数上限不变，但输入略有增加。

这些规则改善选材和教学结构，不等于自动事实核验。索引与例题结构校验不能证明演算正确；仍需人工检查。默认逐 P 生成及资料合并不做语义重编；另选综合教程模式才会在额外确认后跨视频重编。

讲义生成规则升级后，旧草稿仍保留，不会自动改写或调用模型。重新处理原视频或导入字幕会按新规则生成新草稿并消耗额度；同一规则下成功生成的草稿仍可复用。

## 数据与隐私

- **整理请求的模型输入**：字幕、学习目标和主动提供的参考文本；画面模式另经用户确认后发送采样图片。不包含账号 Cookie、媒体签名地址、成品保存路径或整个 pi 会话历史。
- **账号凭据**：本插件的凭据文件仅在本机保存，不加密。POSIX 使用 `0600` / `0700` 权限，Windows 依赖文件 ACL。
- **浏览器登录**：只使用已安装的 Edge/Chrome，不下载浏览器，不读取日常浏览器配置或其他工具的凭据。用户在 Nibblearn 专用窗口自行登录并处理验证码，程序只读取其中的 Bilibili 会话并通过只读接口验证身份。
- **授权保存**：昵称和 UID 只通过本地对话框确认，Cookie 不显示、不发送给模型或聊天。未确认保存不会替换插件原有凭据。登录和检查由用户操作触发，没有持续后台轮询；登录流程最多等待 10 分钟。
- **专用配置**：Edge 与 Chrome 的配置分别保存，不能混用。专用浏览器会保留已完成的登录状态，包括取消保存时；流程结束仅关闭本次专用窗口，不关闭日常浏览器。请勿分享凭据文件、浏览器配置或含登录信息的截图，仅在可信终端或 RPC 客户端操作。
- **文件保存**：重复保存相同内容会复用已有文件；内容不同时新增 `--v2` 等版本。修改输出目录不会搬迁或删除旧文件。

## 当前限制

- 支持字幕与离散采样画面，不提供音频转写或连续视频理解，也不自动选片或定时学习。跨视频综合与学习辅助均须另行确认，不自动启动。
- 笔记生成不自动浏览网页或独立核查事实。模型补充标注为“未检索核验”，参考文本标注为“用户提供，未独立核验”。
- 时间戳与证据索引经过存在性检查，但引用不代表语义正确、字幕完整、画面覆盖全程或观点已证实。
- 不执行评论、私信、点赞或投稿等平台写操作。遇到验证码、限流、预览或访问限制时停止，不尝试绕过；不支持的分段流或编码会明确报错，不会只处理第一段却声称完整。

<details>
<summary>材料大小、模型用量与重试</summary>

- 单份字幕最多 `120,000` 字符，每个分 P／材料生成任务最多 `12` 次分段模型请求；`course` 将多个单 P 任务顺序执行，累计上限会在确认对话框中列明。
- 单次输出不再固定限制为 `4,500 tokens`，默认采用 pi 当前模型声明的最大输出量（`maxTokens`）。输入占用较大时，按剩余上下文空间降低本次输出上限，不截断输入材料。
- 上下文预算以文本 UTF-8 字节数、每张图片预留 `8,192 tokens` 和 `1,024 tokens` 安全余量估算，不是精确分词或计费结果。模型限制配置无效或没有剩余输出空间时，在请求前报错；实际限制仍以服务端为准。
- 最大输出量是允许的上限，不要求模型写满；部分模型的推理也占用输出预算。请求会提示实际输出容量，要求优先完成完整结构、减少重复内容。放宽上限可能增加耗时与费用，笔记结构与证据校验仍然保留；提示不能保证模型永不截断。
- 模型返回 `length` 时报告 `MODEL_OUTPUT_LIMIT`，返回 `error` 时报告 `MODEL_RESPONSE_ERROR`；请求抛错、空正文及其他非正常结束分别报告，不再把服务异常一概说成“可能达到输出限制”。不回显底层错误原文，也不会自动重试。
- 材料超过限制会明确报错，不静默截断。长材料按段整理，当前没有额外的跨段综合请求。
- 每份参考文本最多 `8,000` 字符；计划最多包含 `10` 份参考材料，合计最多 `16,000` 字符。
- 嵌套模型不提供工具，不执行材料中的命令，不联网查资料。
- 成功调用的嵌套模型用量计入 pi 会话。失败时若服务返回用量，会保存在任务记录；服务没有返回用量时无法确定实际计费。
- 复用草稿不会再次调用整理模型，也不会因输出上限调整而自动重新生成；宿主调度工具的普通对话请求仍可能消耗额度。
- 单份材料的 `/learn retry` 仍从头整理，保留历史用量记录；教程综合和学习辅助则在用户重新确认后复用各自成功的章节／批次。均不会自动重试或发布文件。

</details>

生成笔记需要核对原始材料，不应作为个性化医疗、法律或投资建议。
